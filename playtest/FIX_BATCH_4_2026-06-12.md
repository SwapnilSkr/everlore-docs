## D — location dedup  ✅ forward fix
**Root cause:** the memory-mention path `resolveOrCreateEntities` (entity-graph.service)
keyed dedup on `normalizeEntityName` (article-KEPT) and never used the fuzzy/area
resolver — so "the Wildwood" / "Wildwood" / "Wildwood Forest" minted 3 nodes, while the
cursor path (`resolveLocationAnchor`, article-stripped + fuzzy) stayed clean.
**Fix:** route every location-type memory mention through `resolveLocationAnchor`
(`viewpointMoved:true`); store the resolved entity under the article-kept key the caller
looks up by. New mentions now dedup against the cursor's atlas.
**Existing dupes:** forward-only — old QA instances keep their duplicate nodes. The
`merge:location` tool can collapse them on request (not auto-run; merging many nodes is
not reversible).
